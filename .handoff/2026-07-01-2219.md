# Handoff — deep-memory v1.0.3 shipped

## Status

Plugin v1.0.3 deployed, DB verified, committed + pushed to `alejo54dev/deep-memory`.

## What changed (v1.0.1 → v1.0.3)

### Recall fix (root cause)
- `sanitizeFtsQuery` was stripping hyphens, destroying compound tokens like "deep-memory" before FTS5 could tokenize them. Recall always returned 0 hits.
- Fix: lowercase + keep hyphens + split on `[\s-]+` + OR join (was AND).

### FTS5 schema v2
- Tokenizer: `unicode61 remove_diacritics 1` (case + diacritic insensitive).
- Content normalized lowercase before insert (consistent with FTS5).
- `PRAGMA user_version = 2`.

### Hashing
- SHA-1 via `node:crypto` (native in Bun).
- `content_hash` = 40 hex chars of `role + ":" + content`.
- `session_id` = 40 hex truncated to 16 chars of worktree path.
- Chosen over MD5 (32) and SHA-256 (64) as middle ground.

### Logger
- Async buffer + 1s flush interval + 10MB rotation (keep 3 files).
- `process.once("exit")` registered, removed in `dispose`.

### Correctness
- `INSERT OR IGNORE` on `idx_turns_dedup` (was try/catch).
- `stmtSearch` cached (2 variants: with/without age filter).
- `WeakMap<string, ...>` → `Map` (strings not valid WeakMap keys — latent bug).
- `isRealUserMessage`: dropped length<300 limit, added system-reminder filter.
- `extractText`: filters system-reminder and system tags.
- `tokenize`: lowercase + split on hyphens (consistent with FTS5).
- `clampOptions`: validates + limits all config values.
- Dedup O(n) with fingerprint Set.

### Metrics
- `recallCount`, `hitCount` in SessionState.
